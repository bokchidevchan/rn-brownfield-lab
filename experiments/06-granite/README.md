# 06. granite: 05를 프레임워크로 하면 어떻게 되나

Toss 의 granite 를 실제로 적용해 보고, 05번(Re.Pack + Module Federation 직접 조립)과 무엇이 다른지 정리한 실험입니다.

`create-granite-app` 으로 앱을 만들고, 빌드하고, 에뮬레이터의 Granite 테스트 앱(셸) 안에서 화면이 뜨고 라우팅되는 것까지 확인했습니다.

## 한 줄 요약

05번에서 손으로 조립한 것(번들 분리, 공유 런타임, 원격 로드, 서버, 배포)을 granite 는 프레임워크로 제공합니다. 대신 앱의 형태(파일 라우팅, 셸 구조, 배포 인프라)가 granite 방식으로 고정됩니다. Re.Pack 은 번들러이고 granite 는 프레임워크라는 한 문장이 거의 모든 차이를 설명합니다.

## 해 본 것

```bash
npx create-granite-app@latest showcase --tools biome
cd showcase && npm install
npm run build     # dist/ 에 android, ios 번들. esbuild 라 5초대
npm run dev       # 8081 dev 서버
```

에뮬레이터 검증은 Granite 테스트 앱으로 합니다. 셸 앱(APK)을 GitHub Releases 에서 받아 설치하고, `adb reverse tcp:8081 tcp:8081` 후 앱에서 "Run on Dev Server" 를 누르면 dev 서버의 번들이 셸 안에서 뜹니다. pages/ 의 파일 라우팅(index → about 이동)까지 에뮬레이터에서 동작 확인했습니다.

## 구조가 05와 어떻게 다른가

**05 (Re.Pack + MF, 직접 조립)**

- 호스트 앱이 RN 런타임을 소유하고, 피처는 Module Federation 컨테이너로 원격에서 옵니다.
- 공유는 런타임 협상입니다. 호스트가 공유 스코프에 react 를 등록하고, 피처가 빌려 씁니다.
- 네이티브 셸, 번들 서버, 실패 처리, 재시도, 배포 전략 전부 우리가 만듭니다.

**granite**

- 셸 앱(브라운필드 SDK 를 얹은 네이티브 앱)이 'shared' 라는 예약 이름의 공유 번들을 먼저 평가합니다. RN 런타임, react, 공통 라이브러리가 그 안에 있습니다. 프레임워크 소스에 `ENTRY_BUNDLE_NAME = 'shared'` 로 박혀 있고, 서비스가 이 이름을 쓰려 하면 막습니다.
- 각 서비스는 `granite://<appName>` URL 스킴으로 열리는 마이크로앱입니다. 서비스 번들은 공유 번들 위에 얹히므로 작아질 수 있습니다(공식 주장 200~300KB).
- 화면은 pages/ 디렉토리의 파일 라우팅으로 만듭니다. 05의 "호스트가 FEATURES 목록을 알고 import() 한다" 대신 "셸이 스킴 URL 로 서비스를 연다"입니다.
- 번들러는 esbuild 기반 자체 구현(mpack)입니다. Metro 도 Rspack 도 아닙니다. 1200 모듈 빌드가 android, ios 동시에 1~5초입니다.
- 배포는 pulumi 로 AWS CDN 을 세우고 forge CLI 로 올리는 것까지 프레임워크에 포함돼 있습니다. 05에서 우리가 만든 로깅 서버와 07에서 만들 배포 전략의 자리입니다.

같은 문제(프레임워크 중복 없이 화면을 독립 배포)를 05는 런타임 공유(MF 공유 스코프)로, granite 는 빌드 계약(셸에 내장된 공유 번들 위에 서비스 번들을 얹기)으로 풉니다. MF 는 호스트가 떠 있으면 무엇이든 붙는 유연함이 있고, granite 방식은 셸과 서비스의 버전 계약이 선명한 대신 셸 바깥에서는 서비스가 못 뜹니다.

## 숫자로 본 차이

| | 05 Re.Pack | 06 granite (OSS 기본) |
|---|---|---|
| 빌드 시간 (JS) | 호스트 약 4초 (Rspack) | 양 플랫폼 합쳐 1~5초 (esbuild) |
| 피처/서비스 번들 | 152KB + 3KB (실측) | 공유 번들 셸 전제 시 200~300KB (공식 주장) |
| 기본 빌드 산출물 | 호스트 934KB + 피처들 | 통짜 3.9MB JS, HBC 1.4MB |
| 셸 앱 크기 | 우리가 만든 앱 (수십 MB) | 테스트 앱 APK 169MB |
| Hermes 컴파일 | 기기에서 (또는 별도 파이프라인) | 빌드 타임에 .hbc 산출 (plugin-hermes) |

두 가지를 짚어야 공정합니다. granite 의 200~300KB 는 공유 번들을 가진 셸이 전제인 수치이고, OSS 템플릿의 기본 `granite build` 는 RN 을 통째로 담은 1.4MB HBC 를 만듭니다(공유 번들 분리를 쓰려면 plugin-micro-frontend 로 host/remote/shared 를 직접 구성해야 하며, 이 개념은 MF 와 같습니다). 반대로 05의 152KB 도 호스트 앱이 934KB 런타임을 들고 있어야 하는 수치입니다. 어느 쪽이든 "작은 피처 번들"은 런타임을 누군가 미리 들고 있어야 성립합니다.

테스트 앱 169MB 는 디버그 심볼과 모든 공용 네이티브 라이브러리(내비게이션, 리스트, lottie, 비디오 등)를 다 실은 개발용 셸이라 그렇습니다. granite 의 native-packages 목록이 곧 "셸에 미리 실어 두는 네이티브 모듈 표준 셋"인데, 이게 이 아키텍처의 특징을 잘 보여줍니다. 서비스는 그 셋 안의 네이티브 모듈만 쓸 수 있습니다. 05에서도 같은 제약이 있었습니다(피처는 호스트에 autolink 된 네이티브 모듈만 사용 가능). 원격 배포되는 JS 는 네이티브를 새로 들고 갈 수 없다는 제약은 방식과 무관하게 동일합니다.

## 적용하면서 부딪힌 것

- `granite build` 는 watchman 을 부릅니다. 이 머신의 watchman 이 깨져 있어서(icu4c 버전 불일치) 빌드가 에러 없이 무한 대기했습니다. `brew reinstall watchman` 으로 해결.
- `granite dev` 는 metro-file-map 의 파일 감시를 쓰는데 watchman 을 안 쓰도록 고정돼 있어서(NodeWatcher 폴백) macOS 의 FSEvents 스트림 한도(프로세스당 약 4천 개)에 걸려 EMFILE 로 죽었습니다. 프로젝트 디렉토리가 6800개라 한도를 넘습니다. `npm i -D fsevents --ignore-scripts` 로 FSEventsWatcher(스트림 1개)를 쓰게 하면 해결됩니다.
- 공개된 테스트 앱(셸)은 릴리스 0.1.23 의 APK 가 마지막입니다. 최신 프레임워크(1.0.39, RN 0.84)로 만든 앱을 붙이면 셸이 'shared' 등록을 못 찾아 죽습니다. 프레임워크를 0.1.23, RN 0.72.6, react 18.2.0 으로 맞추면 정상 동작합니다. 셸과 서비스의 버전 계약이 얼마나 강한 결합인지 보여주는 사례라서, 도입한다면 셸을 직접 빌드해 관리하는 것까지가 세트입니다.

## 판단

granite 를 쓰는 게 나은 경우

- 마이크로앱을 여러 팀이 계속 찍어내는 조직. 파일 라우팅, 빌드, 배포 인프라, E2E 까지 일관된 틀이 이미 있습니다.
- Toss 처럼 슈퍼앱 셸 하나에 서비스 수십 개를 얹는 구조. 이 프레임워크가 그 모양대로 설계돼 있습니다.

05처럼 직접 조립하는 게 나은 경우

- 기존 브라운필드 앱에 화면 몇 개를 얹는 수준. granite 의 셸 구조까지 도입하는 건 과합니다.
- 번들 분리 전략을 우리가 통제해야 할 때. MF 의 공유 스코프는 피처마다 다른 조합이 가능하지만, granite 는 셸의 공유 번들이 기준입니다.
- RN 버전을 우리가 정해야 할 때. granite 는 프레임워크가 RN 버전을 따라가고, 셸과 서비스가 함께 움직여야 합니다.

취향 문제가 아니라 조직 형태 문제에 가깝습니다. 서비스가 늘어날수록 granite 쪽 저울이 내려가고, 통합 지점이 한두 개면 직접 조립이 가볍습니다.

## 한계

- 검증은 Android 에뮬레이터에서 했습니다. iOS 셸(granite_ios.zip)은 공개 릴리스에 없어서 시뮬레이터 검증을 못 했습니다.
- 공유 번들을 가진 셸을 직접 빌드하지 않았으므로, 서비스 번들이 실제로 200~300KB 로 나오는 것은 재현하지 못했습니다. 공식 수치로만 적습니다.
- dev 서버 경유라 프로덕션 CDN 배포(forge, pulumi)는 돌리지 않았습니다. AWS 계정이 필요합니다.
